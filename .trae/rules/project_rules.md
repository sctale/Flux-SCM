# Flux-SCM 项目规则

## 版本发布规范（强制）

每次升级或大改动完成后，必须执行以下完整流程：

### 1. 版本号更新
- 根据实际改动幅度递增版本号，不要复用已有版本号
- 新增功能 → 次版本号 +1（0.7.2 → 0.8.0）
- Bug修复/小优化 → 修订号 +1（0.7.2 → 0.7.3）
- 破坏性更新 → 主版本号 +1（0.7.2 → 1.0.0）
- 同步更新 `package.json` 和 `server/index.ts` 中的版本号

### 2. 代码提交
- 提交所有改动到 git
- commit message 遵循规范：feat/fix/chore: 中文描述

### 3. 推送到 GitHub
- 推送到 main 分支
- 确保远程代码与本地一致

### 4. 创建 Release
- 创建新的 git tag（如 v0.8.0）
- 通过 GitHub API 创建 Release，draft: false
- Release Notes 包含：功能列表、修复内容、技术栈、与上一版本的差异
- 不要复用已存在的 tag 或 release

### 5. 清理检查
- 确认无残留的 draft release
- 确认旧版本 tag 不会被覆盖
- 确认 GitHub 上的代码与本地一致

## 交流方式
- 始终用中文回答
- 代码注释用中文
- 回答格式：先给结论/核心代码，再解释原因
